## Items Investigated but Not Considered Defects

1. **Missing `history` field:** The data model permits older attendance documents without a `history` field. Treating missing history as an empty list is compatible with the model.
2. **Missing derived fields:** Missing `half_day`, `late_minutes`, or `overtime_minutes` fields can be handled using the defaults specified in the data model.
3. **Weekend attendance trends:** Weekend dates must remain in the trend response. Their presence is not a defect; the attendance-rate rules determine whether their rate is `null`.
4. **Employees without attendance records:** These employees must still contribute to department headcount when they meet the join-date criteria.
5. **HTTP error responses:** Returning `404`, `409`, `422`, or `503` for the corresponding documented conditions is expected behavior, not a defect.
6. **Indexes created at startup:** Creating indexes during startup is appropriate when index creation is idempotent and supports the required query patterns.

## Verification Notes

The items above describe defects or requirements to investigate. Each item should be retained as a confirmed starter defect only if the original starter code exhibited the problem and the final implementation corrected it. Tests should be run against the relevant edge cases, particularly overnight shifts, concurrent updates, rounding, aggregation correctness, and execution plans.
